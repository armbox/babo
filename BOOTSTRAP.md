# Bootstrapping Babo

`babo.babo` is a `.babo` file that describes how to build the Babo CLI tool itself. Feed it to `babo` and it produces a working clone — Babo compiled by Babo. This isn't just a neat trick. It's the core thesis of the language.

## What Bootstrapping Means Here

```
babo.babo  ──▶  babo (existing)  ──▶  babo (clone)
 (spec)         (current compiler)     (new compiler)
```

The `.babo` file contains a specification — written in plain English — of what the Babo CLI should do. The existing `babo` reads that specification, calls an AI backend, and produces a new `babo`. The output is a fully functional, pip-installable Python package with the same CLI, the same cache system, the same module system, and the same build pipeline.

## Why This Matters

### Specifications Outlive Implementations

When you develop something in an interactive AI session, the result is a snapshot — code generated by a specific model at a specific moment. You can't replay that session. If the model improves next month, your old session is stuck in the past.

A `.babo` file is different. It captures *what you want*, not *how it was built*. When a better model arrives, you run the same `.babo` file again and the better model produces a better implementation. The specification stays constant. The implementation improves automatically.

### Decoupling Intent from Agent

Babo has a deliberate one-step-removed relationship with AI agents. It doesn't embed a model. It doesn't couple to a specific API. It says: *"Here is what I want. Whatever sufficiently intelligent system you have, use it."*

This means:

- **Model upgrades are free.** When Claude Opus 5 or Codex Next or whatever comes next, your `.babo` scripts don't change. They just produce better results.
- **Agent diversity is a feature.** The same `.babo` file can be compiled by different backends — Claude Code today, something else tomorrow. The specification is portable.
- **Reproducibility without freezing.** An interactive session is ephemeral. A `.babo` file is reproducible, but unlike a frozen Docker image, it produces an *improved* result when the underlying AI improves.

### The Bootstrap as Proof

`babo.babo` proves the concept by example. It's a non-trivial specification — a multi-file Python package with caching, virtual environments, module systems, shebang support, and a CLI — described entirely in natural language. Running it produces the tool that can run it. This is the same kind of self-hosting that gives a compiler credibility: if the language can express itself, it can express anything.

## The Philosophy

Interactive AI development is powerful but ephemeral. You get a result, but you can't replay the process that produced it. Babo scripts invert this: they capture the *specification* of what you want, and the process is re-invoked fresh each time.

Write the spec once. Run it today. Run it again next year with a better model. The spec is stable. The implementation gets better. That's the point.
